# 局内组合搜索重构规格
## 目标与边界
以 CombatSolver 的主搜索组合和 Smart 药水分层思想替换生产逐轮加宽。一次搜索只由宽度、途中评价、路线保留、用药限制四个维度描述。所有成员同一真实根开始，顺序运行；不引入固定前缀、专项补救链、多堆、学习调度或新模拟语义。最终路线统一比较，四维配置不可绕过玩家约束。
本规格来自用户已确认方向。生产仅时间、内存上限；节点计数保留为诊断，不能存在隐藏节点上限。旧编码/Golden 可继续使用明确隔离的 legacy 执行路径，不能让正式 Mod、OfflineHost、离线新入口默默退回 widening。

高：基准450、窄300、宽675、进攻180、180秒。
极高：基准675、窄450、宽1013、进攻270、300秒。
能力优先、第二排名段、基础分成员用基准宽度。直接存最终数值，不出现倍率概念/字段/注释。独立内存设置，沿用当前默认预算口径但不得假称限制了游戏总RSS。
## 架构与目录
保留 Core/Simulation、Ai/Run、Autoplay、Import、Mod、OfflineHost 现有依赖。
Ai/Combat 根放 CombatSearchRequest、CombatSearchResult、SearchPlan、SearchCodec。
Scheduling: CombatSearchCoordinator、SearchPresets、PortfolioBuilder、PotionSearchSchedule。
Search: 单次 BeamSearch/BeamSolver 主循环、ActionExpansion、SearchProgress。允许保留兼容类名，不追求机械改名。
Retention: RetentionPolicy、CandidateSelector（统一排序、保护代表、配额和补位）。
Storage: CandidatePool（统一去重与分批压缩）、RouteStore（可复用已有路由节点结构）、SearchStorage（跨成员复用）。
Budget: SearchBudget、SearchMemoryBudget。
Policy/Scoring/Quality 复用现有实现，分别负责玩家目标约束、途中评价、完整路线比较。
按职责提取真实实现，不得只是新增DTO/空壳包住旧巨型求解器。也避免大量单方法接口和热路径对象分配。
## 请求与结果
不可变请求包含根、规则、目标约束、档位/自定义配置、总时间/内存。用药限制必须与玩家保护/强制指令相交。所有入口共用编译与协调器。
结果区分完整胜利、找到完整败局、未完成、取消/失效；节点数与终止原因独立。未找到胜利不能解释为证明必败。不采纳不合法/失效/违反强制指令的路线。所有成员统一 RouteQuality 比较，保留 incumbent 和可用进度，保持自动执行重放验证。
统计每成员计划/实际宽度、四维标识、ran/skippedReason、时间、展开数、停止原因、胜负/掉血/用药、是否采纳、逻辑内存/候选池高水位；整个请求的总量不能只报选中成员。
## 调度与预算
主成员顺序：能力优先（有适用能力才加入）、窄、宽、第二段、基础分、限时进攻。参照 /home/rankyu/ss/CombatSolver @ a62f1850 源码；不盲目复制节点预算或专用超额预算。
Smart 无强制指令先无药基线，再有限个允许用药搜索；不为每种药物组合或每个数量机械运行六成员。用药数量分层包含至少一次广泛允许用药的机会，不能无限按数量循环；可利用用户策略和药水可用性决定跳过。第一版选择并文档化简单固定顺序/时间份额。
总绝对截止时间贯穿建成员、搜索、整理和药水阶段；成员限时不重置总限时。为药水阶段保留份额，提前完成可转移剩余时间。取消应及时且传播，整理/大排序有合理检查点。不要用 int.MaxValue 假装无节点限额而不审计相关判断；建议新路径显式无节点预算。
内存整请求统一，跨成员复用，容量达到不能绕过预算。处理上次成员占用/路由历史/辅助数组，避免保留活引用污染下一成员。上限是已分配搜索存储，不是有效候选数，也不是硬RSS。
## 简单内存方案
保留现有统一去重、历史标签与统一筛选。结束回合池在独立可配置阈值触发分批压缩，使用相同 CandidateSelector，压缩目标大于最终W且小于触发阈值；目标与阈值具体数值由实现提议、实验验证（初始建议保留8W、触发16W，并受内存容量限制）。不能每个成员先分配按巨大最大池容量计的全部辅助数组。压缩后复用位置；及时清理失去引用的路由历史。普通出牌池先保持算法，不做多堆。批次压缩是可能改变搜索质量的有意行为，仅新路径启用，单独对照开启/关闭。
