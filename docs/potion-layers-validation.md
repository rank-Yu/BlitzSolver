## 预算修复前的对照与根因

单独使用 `a3b5c86` 和当时的分层版也做过一次同条件的顺序 120 场：两组均为 87 胜、主动用药 18、全部 120 场累计掉血 3,967、共同 87 胜累计掉血 1,850，逐根胜负、HP 和药水列表一致。基线/分层的搜索总耗时分别为 915,015 / 985,124 ms，P95 为 18,808 / 22,469 ms，逻辑内存峰值为 518,928,126 / 458,505,716 B，采样工作集峰值为 688,029,696 / 723,038,208 B；各有 3,948 次池丢弃，0 内存停止。丢弃分别发生在 REGENT-008 的 158 次、REGENT-012 的 315 次、REGENT-015 的 3,475 次。

源码核对发现，`43efcbb` 改为向 `StatePoolBudgetBytes` 写入 64 位预算，但 `ActionExpansion.EffectivePoolStateBudgetBytes` 当时仍只读取旧的 `PoolStateBudgetBytes`，没有显式旧字段覆盖时落到 200 MiB 默认池预算；历史 `1e354bc` 则把预算写入旧字段。独立修复后优先读取新字段、保留旧字段和 200 MiB 回退，并让新颖度搜索安全计算容量；最终配对的池丢弃均为零。该修复没有提高计划宽度、总时间或总内存预算。
